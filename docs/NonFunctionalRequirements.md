## 2. 可用性

| 項目 | 要件 |
| :--- | :--- |
| 目標稼働率 | 70%以上 |
| 計画メンテナンス | 水・金（10:45〜12:15）に実施 |
| 障害検知 | サーバーダウン時に手動対応（自動フェイルオーバー非対応） |

> 大学内利用を主目的とするため、高可用性クラスタ構成は採用しない。

---

## 3. 性能

| 項目 | 要件 |
| :--- | :--- |
| 想定同時接続数 | 通常時 30人以下、ピーク時（授業切替）100人以下 |
| レスポンスタイム | 静的ページ：500ms以内、APIレスポンス：2秒以内 |
| gunicorn ワーカー数 | 3（`2 × CPU + 1` の最小構成） |
| 静的ファイルキャッシュ | nginx により配信、ブラウザキャッシュ活用 |

---

## 4. セキュリティ

| 項目 | 要件 |
| :--- | :--- |
| 通信暗号化 | HTTPS（TLS 1.2 / 1.3）必須。証明書は `/etc/nginx/certs/` にマウント |
| HTTP→HTTPSリダイレクト | 証明書配置時に nginx entrypoint が自動で強制リダイレクト |
| 不要ポートの閉鎖 | 公開ポートは 80 / 443 のみ。SSH は鍵認証かつ学内からのみ許可 |
| gunicorn 外部非公開 | ポート 8000 はコンテナ内部通信のみ（ホスト公開なし） |
| ファイアウォール | `ufw` で 22（SSH）/ 80 / 443 のみ許可 |
| パッケージ更新 | OS・依存ライブラリを月1回以上アップデート |

---

## 5. 保守性

| 項目 | 要件 |
| :--- | :--- |
| デプロイ方式 | `deploy.sh` によるワンコマンドデプロイ |
| 設定変更 | nginx conf・エラーページの変更は再ビルド不要（ボリューム経由） |
| ログ確認 | `docker compose logs -f` で各コンテナのログを統合確認 |
| バックアップ対象 | `data/` ディレクトリ（CSVファイル群）を定期的に手動バックアップ |
| コード管理 | GitHub リポジトリで管理、`main` ブランチが本番対応 |

---

## 6. 運用・監視

| 項目 | 要件 |
| :--- | :--- |
| ログ保持 | nginx アクセスログ・エラーログを 30 日間保持 |
| リソース監視 | `htop` / `df -h` による手動確認（自動監視ツールは非採用） |
| ディスク使用量 | 100GB SSD のうち OS + Docker + データで 20GB 以内を目安 |
| SSL証明書期限 | 有効期限1ヶ月前に手動更新（Let's Encrypt 利用時は自動更新設定推奨） |

---

## 7. 制約・前提条件

- 本システムは学内利用を主目的とするが、学外からのアクセスを許容する。
- データ（CSV）はスプレッドシートからスクリプトを用いてGitHub経由で更新する運用とする
- VPS の物理障害・ConoHa 側の障害については対応不可（SLAに準拠）
- 本番環境に対するスケールアップは、利用者増加時に ConoHa コントロールパネルから対応する
